# Extreme Sudoku: план реализации

Основан на спеке [2026-10-09-extreme-sudoku-design.md](../specs/2026-10-09-extreme-sudoku-design.md).
Ссылки вида "спек 3.2" указывают на разделы спека.

## Принципы исполнения

- Каждый этап делается в отдельной ветке и вливается в `main` через pull request с зелёным CI.
- Внутри этапа порядок: тесты, затем реализация, затем `tsc --noEmit`, `prettier --check`, `vitest run`.
- Этап считается закрытым, когда выполнены все критерии готовности из его раздела.
- Генерация банка (этап 5) долгая; она запускается в фоне, а работа над этапами 6-8 идёт параллельно.
- Никаких эмодзи в коде, комментариях, коммитах и документации; без строк соавторства в коммитах и PR.

## Этап 2. Основа движка

Ветка `engine/core`. Спек 2.3, 4.5.

- [ ] `engine/grid.ts`: индексы клеток, строк, столбцов, блоков; таблица соседей; маски кандидатов;
      разбор и печать строки из 81 символа; вычисление кандидатов по цифрам.
- [ ] `engine/solve.ts`: перебор на битовых масках с выбором клетки с минимумом кандидатов;
      `countSolutions(grid, limit = 2)`, `solve(grid)`; случайная полная сетка по генератору случайных чисел с seed.
- [ ] `engine/random.ts`: детерминированный ГПСЧ (например, mulberry32).
- [ ] `engine/transform.ts`: тип `Transform` (перестановка цифр, полос, строк внутри полос, стеков,
      столбцов внутри стеков, транспонирование), `randomTransform`, `applyTransform`, `fingerprint`
      (инвариантный отпечаток).
- [ ] Тесты по спеку 9.1 (перебор, трансформации, отпечаток).

Готово, когда: перебор решает 1000 случайных задач быстрее секунды в Node, все тесты зелёные.

## Этап 3. Решатель: базовые техники

Ветка `engine/solver-basic`. Спек 3.1, 3.2.

- [ ] Тип `Step` и роли подсветки (спек 2.3); функция применения вывода к сетке.
- [ ] `engine/solver.ts`: цикл "первая сработавшая техника", ограничение по максимальному рейтингу
      (нужно для быстрого фильтра генератора), результат: список шагов, решена ли сетка, рейтинг.
- [ ] Техники: Hidden/Naked Single; Pointing, Claiming; Naked/Hidden Pair, Triple, Quad;
      X-Wing, Swordfish, Jellyfish, finned X-Wing, finned Swordfish; XY-Wing, XYZ-Wing;
      Unique Rectangle 1, 2, 4; BUG+1.
- [ ] `engine/rating.ts`: таблица рейтингов техник.
- [ ] Тестовая обвязка корректности: решатель на N случайных задачах, каждый вывод сверяется с решением.
- [ ] Позиции-примеры для каждой техники: срабатывает с точным выводом и не срабатывает.

Готово, когда: обвязка корректности проходит на 500 случайных задачах, все примеры зелёные.

## Этап 4. Решатель: цепи, ALS, forcing chains

Ветка `engine/solver-advanced`. Спек 3.2, 3.5.

- [ ] Граф связей: сильные и слабые связи внутри клетки и внутри группы для одной цифры.
- [ ] Поиск AIC в ширину с возвратом кратчайшей цепи; исключения на пересечении концов;
      классификация: Skyscraper, 2-String Kite, W-Wing, X-Chain, XY-Chain, AIC; надбавка за длину.
- [ ] ALS: перечисление ALS до 4 клеток (больше не нужно для заявленного диапазона); ALS-XZ, ALS-XY-Wing.
- [ ] Forcing chains: распространение допущения одиночками и исключениями от цифр с лимитом длины;
      Cell forcing chain и Unit forcing chain; вывод из противоречия и из общего следствия; рейтинг по длине.
- [ ] Описание цепей в `Step` (список связей для отрисовки).
- [ ] Калибровочный набор известных задач в `tests/fixtures/calibration.json` и тесты по спеку 3.5.
- [ ] Тест скорости: полный рейтинг экстремальной задачи в среднем десятки миллисекунд, худший случай меньше секунды в Node.

Готово, когда: обвязка корректности проходит, калибровка совпадает с ожиданиями спека.
Если калибровка не сходится, корректируются значения в `rating.ts`, а не порог банка.

## Этап 5. Генератор банка

Ветка `generator`. Спек 4.

- [ ] `scripts/generate.ts`: этап 1 (полная сетка, минимизация, быстрый фильтр до 6.6, полный рейтинг)
      и этап 2 (мутация 1-3 подсказок, минимизация, рейтинг).
- [ ] Дедупликация по отпечатку, ограничение 20 задач на род, квоты 250/175/75.
- [ ] `worker_threads` на все ядра, seed из аргументов, промежуточное состояние в `.generate-state/`
      (в `.gitignore`), продолжение после прерывания, вывод прогресса по квотам.
- [ ] `scripts/verify-bank.ts`: полная проверка банка по спеку 9.2.
- [ ] Тест генератора с пониженным порогом и фиксированным seed; тест банка (полный или выборка 50).
- [ ] Запуск полной генерации в фоне; по готовности коммит `src/data/puzzles.json` отдельным PR.

Готово, когда: банк из 500 задач закоммичен, `npm run verify-bank` проходит.
Если за разумное время (порядка 12 часов) квота 9.x не набирается, вопрос выносится пользователю.

## Этап 6. Логика партии

Ветка `game`. Спек 5, 7.

- [ ] `game/state.ts`: создание партии из задачи банка и трансформации; действия: выбор клетки, цифра,
      пометка, стереть, переключение пометок и авто-кандидатов, undo, redo, применение подсказки;
      история до 500 шагов; определение победы.
- [ ] `game/check.ts`: эффективные кандидаты, ошибки двух видов, видимые конфликты.
- [ ] `game/hint.ts`: подсказка по позиции (сначала ошибки, затем одна итерация решателя).
- [ ] `game/timer.ts`: накопление времени, пауза, фон.
- [ ] `game/pick.ts`: выбор случайной нерешённой задачи, поведение после решения всех 500.
- [ ] `app/storage.ts`: ключи `xsudoku.v1.*`, устойчивое чтение, экспорт и импорт с версией формата.
- [ ] Статистика: записи о решениях и вычисление сводки по спеку 7.3.
- [ ] Тесты по спеку 9.3.

Готово, когда: все действия партии покрыты тестами и проходят.

## Риски

| Риск                                                     | Что делаем                                                                                                      |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Forcing chains слишком медленные для генератора          | быстрый фильтр отсекает большинство задач; лимит длины; профилирование на этапе 4                               |
| Генератор плохо набирает задачи 9.x                      | мутации ориентируются на самые сложные задачи пула; при нехватке вопрос пользователю                            |
| Подсказка на iPhone считается долго                      | Web Worker, индикатор; при необходимости лимит времени на поиск forcing chains                                  |
| Контейнер облачной сессии выгружается во время генерации | промежуточное состояние на диске; при необходимости генерация запускается у пользователя на Mac той же командой |
