# Адресные сообщения по коду устройства: дизайн

Дата: 2026-11-03. Статус: на утверждении.
Дополняет спек [2026-11-03-bank-expansion-and-greeting-design.md](2026-11-03-bank-expansion-and-greeting-design.md).

## 1. Цель

Показать сообщение (карточку поздравления с конфетти и сердечками) конкретному игроку внутри
установленного приложения на экране Домой. Ссылки на iPhone всегда открываются в Safari, у которого
данные отдельные от приложения, поэтому адресация идёт по коду устройства.

## 2. Код устройства

- При первом запуске версии с этой функцией приложение создаёт случайный код из 8 символов алфавита
  без похожих знаков (`23456789ABCDEFGHJKMNPQRSTUVWXYZ`), показывается как `XXXX-XXXX`.
  Источник случайности: `crypto.getRandomValues`.
- Код хранится в настройках (`xsudoku.v1.settings`, поле `deviceCode`) и больше не меняется.
- В окне "Настройки" внизу (над кнопкой "Закрыть"): строка "Код устройства: XXXX-XXXX" и кнопка
  "Скопировать".
- Код никуда не отправляется. Экспорт и импорт данных код не переносят.
- У Safari и у приложения с экрана Домой коды разные (раздельное хранилище iOS).

## 3. Файл сообщений

`public/messages.json`, публикуется вместе с сайтом:

```json
{ "messages": [{ "id": "karina-1", "salt": "...", "iv": "...", "data": "...", "repeat": true }] }
```

- Текст зашифрован: ключ AES-GCM 256 получается из кода устройства (без дефиса, заглавными)
  через PBKDF2-SHA256, 200 000 итераций, соль сообщения. `data` — шифротекст UTF-8 текста, base64.
- Устройство считает сообщение своим, если расшифровка прошла. Остальные устройства его не читают.
- `repeat: true` — показывать каждый раз (см. 4), `false` — один раз.
- Файл не попадает в предкэш service worker и запрашивается с `cache: 'no-store'`.

## 4. Доставка и показ

- Приложение запрашивает `messages.json` при запуске и при возвращении из фона.
- Найденное своё сообщение сохраняется локально (`xsudoku.v1.inbox`): работает и без сети.
  Если в свежем файле сообщения с этим id больше нет, локальная копия удаляется.
- Показ сообщения с `repeat: true`: при каждом запуске приложения и при возвращении в него после
  30 минут и более в фоне. С `repeat: false`: один раз, затем отмечается как показанное.
- Показ использует ту же карточку, что и поздравление по ссылке. Если открыта ссылка-поздравление,
  она имеет приоритет.
- Ошибки сети, битый файл или неподдерживаемый WebCrypto игру не ломают: сообщение просто не показывается.

## 5. Управление сообщениями

`npm run message -- add --id ID --code XXXX-XXXX --text "текст" [--once]` шифрует текст и
добавляет запись в `public/messages.json`; `npm run message -- remove --id ID` удаляет запись.
Перевод строки в тексте: `\n`. После изменения файла нужен PR и публикация, как обычно.

## 6. Тесты

- код устройства: формат, неизменность, отображение и копирование в настройках;
- шифрование: расшифровка своим кодом, отказ чужим, кириллица и переводы строк;
- доставка: показ при запуске, повтор после 30 минут в фоне, однократный режим, удаление
  сообщения из файла, работа без сети по локальной копии, битый файл;
- e2e: с подставленным кодом и файлом сообщений карточка появляется при запуске.
