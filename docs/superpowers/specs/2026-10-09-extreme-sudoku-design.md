# Extreme Sudoku: дизайн

Дата: 2026-10-09. Статус: утверждён пользователем.

## 1. Цель и рамки

Веб-судоку, в котором есть только задачи экстремальной сложности уровня "предел логики": человек решает их
чистой логикой без угадывания, рейтинг примерно 7.0-9.5 по шкале, откалиброванной по Sudoku Explainer (SE).
Задачи уровня SE 10+, требующие вложенных допущений, не входят. Подуровней сложности внутри экстрима нет.

- Основное устройство: iPhone, портретная ориентация. Также работает на компьютере.
- Хостинг: GitHub Pages, репозиторий `reyeslinch1337/sudoku`, адрес `https://reyeslinch1337.github.io/sudoku/`.
- Устанавливается как PWA на экран Домой, работает офлайн.
- Играет в основном владелец, возможно друзья по ссылке. Аккаунтов, сервера, рейтингов игроков и мультиплеера нет.
- Интерфейс на русском и английском с переключателем. Названия техник в обоих языках английские.

Функции:

- базовые: сетка, ввод цифр, режим пометок-кандидатов, undo/redo, стирание, подсветка одинаковых цифр,
  подсветка конфликтов, автосохранение текущей игры;
- дополнительные: авто-кандидаты, проверка ошибок, логические подсказки, таймер и статистика,
  экспорт и импорт данных.

Стек: TypeScript, Vite, Preact, `@preact/signals`, Vitest, Playwright, `vite-plugin-pwa`.

## 2. Архитектура и модули

### 2.1 Структура репозитория

```
sudoku/
  src/
    engine/          чистый TypeScript, без DOM и без Preact
      grid.ts          представление сетки и кандидатов
      solve.ts         быстрый перебор: подсчёт решений (0, 1, больше одного), поиск решения
      techniques/      по файлу на семейство: singles, intersections, subsets, fish, wings,
                       uniqueness, chains, als, forcing
      solver.ts        человекоподобный решатель
      rating.ts        шкала рейтинга
      transform.ts     трансформации с сохранением логики, каноническая форма
    game/            логика партии, без DOM
      state.ts         редьюсер: ход, пометка, стирание, авто-кандидаты, undo/redo
      check.ts         проверка ошибок по решению, эффективные кандидаты
      hint.ts          построение подсказки по позиции игрока
      timer.ts         учёт времени
    app/             интерфейс на Preact
      components/      Board, Cell, NumPad, Toolbar, HintPanel, Menu, StatsScreen, Settings,
                       WinScreen, PauseScreen, UpdateBanner, InstallTip
      i18n/            ru.ts, en.ts
      storage.ts       localStorage, экспорт и импорт
      hint.worker.ts   тонкая обёртка Web Worker над game/hint.ts
    data/
      puzzles.json     банк из 500 задач
  scripts/
    generate.ts      генератор банка, Node, импортирует только engine
  tests/             Vitest (unit и компонентные)
  e2e/               Playwright
  public/            исходная SVG иконки
  .github/workflows/deploy.yml
```

### 2.2 Правило зависимостей

`engine` ни от чего не зависит. `game` зависит только от `engine`. `app` зависит от `engine` и `game`.
`scripts/generate.ts` импортирует только `engine`. Решатель одинаково работает в браузере и в Node.

### 2.3 Ключевые типы

- **Сетка**: 81 клетка. Цифры в массиве чисел (0 означает пусто), кандидаты в массиве 9-битных масок.
- **Step** (шаг решателя): название техники; клетки и кандидаты для подсветки с ролями (опорные, звенья
  цепи, удаляемые); для цепей список связей с типом (сильная или слабая); выводы (поставить цифру или
  удалить кандидаты); параметры для текстового объяснения. Используется и для рейтинга, и для подсказок.
- **Состояние партии**: идентификатор задачи, параметры трансформации, задача, решение, цифры игрока,
  пометки, флаг авто-кандидатов, история undo/redo, накопленное время, счётчики подсказок и проверок.
  Неизменяемый объект; редьюсер возвращает новый, undo/redo реализуется стеком прошлых состояний.

### 2.4 Потоки и состояние в браузере

- Подсказки считаются в Web Worker (`new Worker(new URL(...), { type: 'module' })`), чтобы forcing chains
  не подвешивали интерфейс.
- Состояние партии хранится в сигнале `@preact/signals`; компоненты клеток подписываются на свои данные
  и перерисовываются точечно. Все изменения проходят через редьюсер.
- `puzzles.json` импортируется в бандл (около 45 КБ) и кэшируется service worker вместе с остальным.

## 3. Движок решателя и рейтинг

### 3.1 Алгоритм решателя

Каждая техника реализована функцией `find(grid): Step | null`, которая находит одно применение.
Техники упорядочены по возрастанию рейтинга. Цикл решателя:

1. пройти список сверху вниз и взять первую технику, которая что-то нашла;
2. применить вывод;
3. начать снова с самой простой техники.

Сетка не решена и ни одна техника ничего не нашла: задача нерешаема нашим движком.
Подсказка выполняет ровно одну итерацию этого цикла.

### 3.2 Техники и шкала

Рейтинг задачи равен рейтингу самого сложного шага в её решении.

| Уровень | Техники | Рейтинг |
|---|---|---|
| Одиночки | Hidden Single, Naked Single | 1.2-2.3 |
| Пересечения | Pointing, Claiming | 2.6-2.8 |
| Подмножества | Naked/Hidden Pair, Triple, Quad | 3.0-5.4 |
| Рыбы | X-Wing, Swordfish, Jellyfish, finned X-Wing, finned Swordfish | 3.2-5.2 |
| Крылья | XY-Wing, XYZ-Wing, W-Wing | 4.2-4.6 |
| Уникальность | Unique Rectangle типов 1, 2, 4; BUG+1 | 4.5-5.7 |
| Короткие цепи | Skyscraper, 2-String Kite | 6.6 |
| Цепи | X-Chain, XY-Chain, AIC | 6.6-7.5 |
| ALS | ALS-XZ, ALS-XY-Wing | 7.0-7.8 |
| Forcing chains | Cell forcing chain, Unit (digit) forcing chain | 8.0-9.5 |

Точные значения каждой техники внутри диапазонов фиксируются в `rating.ts` и подгоняются при калибровке (3.5).

- **Единая реализация цепей.** X-Chain, XY-Chain, Skyscraper, 2-String Kite и W-Wing являются частными
  случаями AIC. Реализуется один поиск AIC; имя для подсказки и рейтинг определяются по форме найденной цепи.
  Поиск возвращает кратчайшую цепь из найденных.
- **Надбавка за длину.** Для цепей и forcing chains к базовому рейтингу прибавляется 0.1 за каждые
  2 звена сверх 4, не выше верхней границы уровня.
- **Forcing chains.** Допущение кандидата распространяется только одиночками и исключениями от
  поставленных цифр, без вложенных допущений, с лимитом длины. Вложенные цепи не реализуются.
- **Техники уникальности** включены: все задачи банка имеют единственное решение.

### 3.3 Порог попадания в банк

Все три условия:

1. ровно одно решение;
2. решатель доводит задачу до конца;
3. рейтинг не ниже 7.0.

Верхняя граница образуется сама: задачи сложнее наших forcing chains решатель не решает.

### 3.4 Производительность

Генератор прогоняет решатель миллионы раз, поэтому операции над кандидатами делаются на битовых масках,
а дорогие техники (AIC, ALS, forcing chains) вызываются только когда дешёвые ничего не нашли.

### 3.5 Калибровка

В тестах хранится небольшой набор известных задач с опубликованными рейтингами SE (только для тестов,
в банк они не входят). Проверяется: простые получают низкий рейтинг, задачи около SE 8-9 решаются
и попадают в диапазон 7.0-9.5, заведомо запредельные (например, Easter Monster, SE 11.9) не решаются.

## 4. Генератор банка задач

### 4.1 Конвейер

`npm run generate` запускает `scripts/generate.ts`.

Этап 1, исходные задачи:

1. случайная полная сетка перебором со случайным порядком цифр;
2. удаление подсказок в случайном порядке, пока решение единственное (минимальная задача);
3. быстрый фильтр: решение только техниками с рейтингом до 6.6 включительно; решилась, значит отбросить;
4. полный решатель; рейтинг не ниже 7.0, значит годится.

Симметрия расстановки подсказок не требуется.

Этап 2, мутация: из пула найденных задач берётся задача, меняются 1-3 подсказки (убрать, добавить,
перенести), проверяется единственность, задача минимизируется и рейтингуется. При рейтинге не ниже 7.0
она добавляется в пул и в банк.

### 4.2 Разнообразие

- **Дубликаты**: для каждой задачи вычисляется каноническая форма (лексикографически минимальная
  среди всех трансформаций). Задачи с одинаковой канонической формой считаются одной.
- **Ограничение на род**: одна исходная задача этапа 1 вместе со всеми потомками даёт в банк не больше 20 задач.
- **Квоты по рейтингу** (всего 500):

| Диапазон | Доля | Задач |
|---|---|---|
| 7.0-7.9 | 50% | 250 |
| 8.0-8.9 | 35% | 175 |
| 9.0-9.5 | 15% | 75 |

Генерация продолжается, пока все квоты не заполнены. Лишние задачи заполненного диапазона отбрасываются.

### 4.3 Формат банка

```json
[{ "p": "4.....8.5.3..........7......2.....6.....8.4......1.......6.3.7.5..2.....1.4......", "r": 7.8 }]
```

`p` — задача из 81 символа (`.` для пустой клетки), `r` — рейтинг с одним знаком после запятой.
Решение не хранится и вычисляется перебором при загрузке. Размер файла около 45 КБ.

### 4.4 Практические детали

- параллельная работа на всех ядрах через `worker_threads`;
- детерминированность при заданном seed;
- промежуточные результаты на диске, прерванный запуск продолжается с места остановки;
- ожидаемое время от одного до нескольких часов, уточняется на первом прогоне;
- готовый `puzzles.json` коммитится; CI банк не генерирует.

### 4.5 Выдача задачи игроку

Новая игра берёт случайную нерешённую задачу и применяет к ней случайную трансформацию: перестановка
цифр, перестановка строк внутри полос, перестановка полос, то же для столбцов, транспонирование.
Рейтинг и логика решения при этом не меняются. В партии сохраняется идентификатор задачи и параметры
трансформации. Когда решены все 500, выдаётся случайная задача из всего банка с новой трансформацией.

## 5. Подсказки и проверка ошибок

### 5.1 Эффективные кандидаты

Решатель для подсказки работает на текущей позиции игрока. Кандидаты пустой клетки:

- если в клетке есть пометки игрока: эти пометки минус цифры, уже стоящие в строке, столбце или блоке клетки;
- если пометок нет: все цифры, допустимые по поставленным цифрам.

### 5.2 Ошибки

- **неверная цифра**: поставленная игроком цифра отличается от решения;
- **потерянный кандидат**: в клетке есть пометки, и среди них нет правильной цифры.

Подсказка сначала ищет ошибки. Если ошибка есть, подсказка ведёт к ней, а не строит логику.

### 5.3 Три уровня подсказки

Кнопка подсказки открывает панель под сеткой; каждое следующее нажатие раскрывает следующий уровень.

1. Название техники (например, "XY-Chain"); при ошибке фраза "На поле есть ошибка".
2. Подсветка на сетке: клетки и кандидаты по ролям. Цепи рисуются поверх сетки в SVG: сильная связь
   сплошной линией, слабая пунктиром. При ошибке подсвечивается клетка с ошибкой.
3. Вывод текстом (например, "r7c4 не может быть 5") и кнопка "Применить". Применение — обычный ход
   с поддержкой undo. При ошибке кнопка убирает неверную цифру или возвращает потерянного кандидата.

- Тексты собираются из шаблонов для каждой техники на двух языках; координаты в нотации r1c1.
- Если воркер считает дольше 200 мс, в панели показывается индикатор.
- Ход игрока при открытой панели сбрасывает подсказку.
- Подсказка засчитывается в статистику один раз, при открытии уровня 1.

### 5.4 Кнопка "Проверить"

Сразу подсвечивает все ошибки обоих видов. Каждое нажатие засчитывается как одна проверка,
отдельно от подсказок.

### 5.5 Авто-кандидаты

Переключатель на панели инструментов. При включении пометки всех пустых клеток заполняются допустимыми
цифрами. Пока режим включён, постановка цифры стирает её из пометок клеток той же строки, столбца и блока.
После выключения пометки остаются и редактируются вручную.

## 6. Экран игры и ввод

### 6.1 Компоновка (портрет)

Сверху вниз:

1. верхняя панель: меню, рейтинг задачи числом (без названия самой сложной техники), таймер, пауза;
2. сетка на всю ширину с учётом safe-area; пометки рисуются сеткой 3x3 внутри клетки;
3. панель подсказки (только когда открыта);
4. панель инструментов: undo, redo, стереть, пометки, авто-кандидаты, проверить, подсказка;
5. цифровая панель 1-9 в один ряд; под цифрой число оставшихся мест; цифра, поставленная 9 раз, тускнеет.

В альбомной ориентации сетка слева, панели справа. Все кнопки не меньше 44 pt.

### 6.2 Ввод

Сначала клетка, потом цифра. В режиме пометок нажатие цифры добавляет или убирает пометку в выбранной
клетке. "Стереть" очищает цифру игрока или пометки клетки. Клетки с исходными подсказками не редактируются.

Клавиатура на компьютере: цифры 1-9, стрелки, Backspace и Delete, пробел для переключения режима
пометок, Ctrl/Cmd+Z для undo, Shift+Ctrl/Cmd+Z для redo.

### 6.3 Подсветка

- выбранная клетка, её строка, столбец и блок;
- клетки с той же цифрой, что в выбранной клетке, и эта цифра в пометках;
- конфликты (одинаковые цифры в одной строке, столбце или блоке) красным сразу при вводе.
  Это только видимые повторы; сверка с решением делается только проверкой и подсказкой.

### 6.4 Экраны

- меню: новая игра (с подтверждением, если текущая не закончена), статистика, настройки;
- настройки: язык RU/EN, экспорт, импорт;
- пауза: сетка скрыта, таймер стоит;
- победа: время, число подсказок и проверок, рейтинг, кнопка "Новая игра";
- тема светлая или тёмная по системной настройке (`prefers-color-scheme`), цвета в CSS-переменных;
- язык по умолчанию по `navigator.language` (русский, если начинается с `ru`, иначе английский).

### 6.5 Особенности iPhone

- `viewport-fit=cover`, отступы через `env(safe-area-inset-*)`;
- `touch-action: manipulation` для всего приложения (нет зума двойным тапом и задержки тапа);
- `overscroll-behavior: none`;
- отключены выделение текста, контекстное меню при долгом нажатии, подсветка тапа;
- meta-теги `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `apple-touch-icon`.

## 7. Хранение и статистика

### 7.1 localStorage

| Ключ | Содержимое |
|---|---|
| `xsudoku.v1.game` | текущая партия (см. 2.3), история undo/redo не длиннее 500 шагов |
| `xsudoku.v1.stats` | записи о решённых задачах |
| `xsudoku.v1.settings` | язык; флаг, что совет об установке уже показан |

- Поврежденные или несовместимые данные игнорируются, приложение начинает с чистого состояния.
- Сохранение после каждого хода и при `visibilitychange` (скрытие) и `pagehide`.
- Идентификатор задачи — её строка из банка (81 символ), а не номер.

### 7.2 Таймер

Время копится только пока приложение видимо и не на паузе. Хранится накопленное время в миллисекундах.

### 7.3 Статистика

Запись о решении: идентификатор задачи, рейтинг, время, число подсказок, число проверок, дата.
Решение без подсказок и проверок называется чистым.

Экран статистики показывает, в целом и по диапазонам 7.x, 8.x, 9.x:

- число решённых задач и из них чистых;
- лучшее время только среди чистых решений;
- среднее время по всем решениям;
- прогресс по банку ("решено 37 из 500").

### 7.4 Экспорт и импорт

В настройках: "Экспорт" копирует в буфер обмена строку с версией формата, статистикой и текущей партией;
"Импорт" принимает такую строку, проверяет формат и после подтверждения заменяет локальные данные.

### 7.5 Совет об установке

Safari может стереть данные сайта, не открывавшегося 7 дней; на установленные на экран Домой приложения
это не распространяется. При первом запуске в Safari (не в режиме standalone) показывается ненавязчивый
совет "Добавьте на экран Домой", один раз.

## 8. PWA и деплой

### 8.1 PWA

- `vite-plugin-pwa` (Workbox) генерирует service worker и manifest.
- Service worker заранее кэширует всё содержимое сборки; после первого открытия приложение работает офлайн.
- Manifest: name "Extreme Sudoku", short_name "X Sudoku", `display: standalone`, `start_url` и `scope`
  `/sudoku/`, цвет темы.
- Иконки генерирует `@vite-pwa/assets-generator` из одной SVG: PNG 192 и 512, maskable, apple-touch-icon 180.
- Vite собирается с `base: '/sudoku/'`.
- Обновление: новый service worker скачивается в фоне, приложение показывает баннер "Доступна новая
  версия" с кнопкой "Обновить". Без нажатия страница не перезагружается.

### 8.2 CI и деплой

Один workflow `.github/workflows/deploy.yml`, Node 22 LTS; в `package.json` `engines` `>=22`.

| Событие | Шаги |
|---|---|
| pull request в `main` | `npm ci`, `tsc --noEmit`, `prettier --check`, `vitest run`, сборка, Playwright smoke-тесты |
| push в `main` | то же, затем публикация через `actions/upload-pages-artifact` и `actions/deploy-pages` |

- Строгий режим TypeScript и Prettier; ESLint не используется.
- Работа в отдельных ветках, в `main` через pull request; каждый merge публикует сайт.
- Разовое действие владельца: в настройках репозитория, раздел Pages, выбрать источник "GitHub Actions".

## 9. Тестирование

### 9.1 Движок

- перебор: подсчёт решений (0, 1, больше одного), поиск решения, маски кандидатов;
- трансформации: корректность, согласованность с трансформированным решением, неизменность рейтинга;
  совпадение канонической формы у задачи и её трансформаций;
- каждая техника: позиции-примеры с точно ожидаемым выводом и позиции, где техника не срабатывает;
- классификация цепей: Skyscraper, 2-String Kite, W-Wing, X-Chain, XY-Chain;
- корректность на массе задач: решатель на сотнях случайных задач и на всём банке; на каждом шаге вывод
  не противоречит решению (не удалён правильный кандидат, не поставлена неверная цифра);
- калибровка рейтинга (3.5).

### 9.2 Генератор и банк

- короткий прогон с фиксированным seed и пониженным порогом: задачи с единственным решением, минимальные,
  без дубликатов, результат воспроизводим;
- проверка банка: 500 задач, единственность решения, решатель дорешивает, рейтинг совпадает с сохранённым,
  нет дубликатов по канонической форме, квоты соблюдены. Если полная проверка дольше примерно минуты,
  в `vitest run` проверяется случайная выборка из 50 задач, а полная запускается командой `npm run verify-bank`.

### 9.3 Логика партии

Редьюсер (ход, пометка, стирание, undo/redo, авто-кандидаты и автоочистка), эффективные кандидаты,
ошибки обоих видов, подсказка на позиции с ошибкой, таймер, хранилище (сохранение, загрузка,
поврежденные данные, экспорт и импорт).

### 9.4 Интерфейс

Компонентные тесты (`@testing-library/preact`, `happy-dom`): ввод цифры, режим пометок, три уровня
подсказки и "Применить", экран победы, переключение языка.

### 9.5 End-to-end

Playwright, Chromium с размером экрана iPhone, против production-сборки (`vite preview` с base `/sudoku/`):

1. приложение открывается, сетка и задача на месте;
2. ход ставит цифру, undo отменяет;
3. подсказка проходит три уровня;
4. после перезагрузки партия восстановлена;
5. после первой загрузки приложение открывается без сети.

### 9.6 Ручной чек-лист на iPhone перед первым релизом

Установка на экран Домой, работа без сети, safe-area, отсутствие зума при быстрых тапах, сохранение
партии после выгрузки приложения, баннер обновления.
